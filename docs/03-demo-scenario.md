# 시연 대본 (3분) — 개발의 북극성

여기 나오지 않는 기능은 만들지 않는다. 각 단계의 **화면 / 사용자 행동 / 앱 반응 / 심사위원에게 보이는 가치**를 고정한다.
데이터는 `docs/contracts/seed-data.sql` 기준(김영자 님, 거래 101·102·103).

## 무대 세팅
- **폰(또는 폰 크기로 띄운 브라우저)**: 어르신 화면. 발표용 화면에 미러링.
- **노트북**: 직원 화면 `/staff`. 화면 분할로 동시에 보이게.
- **헤드셋 마이크** 사용. 소음이 심하면 개발자 패널의 "녹음 클립 입력"으로 미리 녹음한 파일을 넣는다(관객에게는 미리 "현장 소음 대비 녹음 클립을 쓰겠습니다"라고 말한다. 숨기지 않는다).
- 시연자 1명(발표자와 별도여도 좋다), 해설은 발표자가.

## 시간 배분
1~2: 30초 / 3~5: 40초 / 6~7: 35초 / 8: 20초 / 9~11: 40초 / 12: 15초 → **약 3분**

## 반드시 지킬 것
- 3·4·6 은 **음성**으로 한다(핵심 가치). 8 은 일부러 실패시킨다. 나머지는 버튼이어도 된다.
- 6 에서 STT 가 "이십만"을 "이시만"으로 잘못 들어도 확인 톤 되묻기가 나오므로 시연은 계속된다. 되묻기가 나오면 "아니에요" → 선택지로 진행. **이것도 시연 포인트다.**
- 코드가 죽으면 즉시 **영상**으로 전환(Day 2 밤 녹화). 발표자는 "영상으로 이어가겠습니다" 한마디만.
