# 후보 대조 레이어 — 텍스트 강건성 측정

`app/core/candidates.py` (자모 분해 + n-gram 창 Levenshtein) 를 서버·네트워크 없이
직접 import 해서 측정한다. **Gemini 호출 없음.**

## 핵심

- 깨진 입력 **200건** (약/중/강 = 60/60/80, 강 왜곡 40.0%) 을 원본 `candidates.py` 로 판정.
- **오실행(위험) 0건 / 200건 = 0.0%.** 틀린 후보를 실행한 경우가 없다.
- 바로 맞힘 31.5% · 안전하게 되물음/버튼 59.0% · 동점보류(LLM 1회) 9.5%.
- 약(1곳 왜곡)에서는 바로 맞힘 66.7%, 강(3곳 이상)에서는 대부분 되물음으로 빠지되 **여전히 오실행 0**.
- `accept` 를 0.70/0.80/0.90 으로 쓸어 보면 0.70 은 오실행 3건, 0.80·0.90 은 0건. 0.80 이 오실행 0 을 지키는 가장 낮은 문턱(= 도달률이 가장 높은 안전 지점)이다. (§3)

## 어떻게 측정했나

- **후보 집합**: `build_candidates(briefing.json, counterparties.json)` → 후보 10개 (TX 3 · CP 3 · INTENT 4)
- **깨진 입력 생성**: 각 후보의 `surface_forms`(정답 표현)에 아래 한국어 STT 오류 패턴을 규칙 적용:

  | 변형 | 내용 | 예 |
  |---|---|---|
  | 연음화 | 받침을 다음 음절 초성으로 | 아들한테 → 아드란테 |
  | 받침탈락 | 종성 제거 | 김철수 → 기철수 / 김처수 |
  | 자음치환 | ㅂ↔ㅍ · ㄷ↔ㅌ · ㄱ↔ㅋ · ㅈ↔ㅊ | 대한정보통신 → 태한정보통신 |
  | 모음혼동 | ㅐ↔ㅔ · ㅗ↔ㅜ | 김철수 → 김철소 |
  | 띄어쓰기 | 공백 삭제·삽입 | 세번째 → 세 번째 |
  | 군더더기 | 앞뒤에 그/저기/음 … | 김철수 → 음 김철수 |

  음성적 왜곡(연음·받침·자음·모음)을 구조적 왜곡(띄어쓰기·군더더기)보다 약 8:2 로 자주 적용했다 — 구조적 왜곡만 걸린 '사실상 무손상' 케이스로 숫자를 부풀리지 않기 위해.

- **왜곡 강도**: 약 = 1곳, 중 = 2곳, 강 = 3곳 이상(3~4). 세 강도는 **같은 표현 모집단**(48종, 강 왜곡이 구조적으로 가능한 것)에서 뽑아 서로 비교된다.
- **표본 수**: 약 60 · 중 60 · 강 80 · **총 200** (강 왜곡 비중 **40.0%**). 이 중 정답 표현이 두 후보에 공통이라 모호한 케이스 25건.
- **판정**: `score_candidates()` → `decide(accept=0.8, ask=0.6, tie_gap=0.1)` (`.env.example` 기본값).
- **재현**: 난수 시드 `20260909` 고정. 전체 테스트셋 → [`testset/text-cases.csv`](../testset/text-cases.csv)
  ```
  cd ai-server && .venv/bin/python tools/measure/text_measure.py
  ```

### 분류 정의

| 분류 | `decide()` 결과 | 뜻 |
|---|---|---|
| 맞음 | ACCEPT + 정답 후보 | 인식이 깨져도 하려던 일에 바로 도달 |
| 위험 | ACCEPT + 틀린 후보 | **오실행. 0 에 가까워야 한다** |
| 되물음 | ASK_AGAIN | 안전하게 실패 ("~ 말씀이세요?" YES/NO) |
| 버튼 | BUTTON | 안전하게 실패 (상위 후보 버튼 제시) |
| 동점보류 | LLM_TIEBREAK | 1위 ≥ accept 이나 2위와 차이 < tie_gap. 실행 안 함, 프로덕션에선 facts 만 준 LLM 1회로 확정 (여기선 호출 안 함) |

> **모호한 정답.** 정답 표현이 두 후보에 공통이면(예: `철수` → `TX:101`·`CP:1`, `물어보기` → 두 INTENT) 정답을 **집합**으로 보고 그 안에 들면 맞음으로 친다. 집합 밖 후보를 고르면 위험이다. 이런 케이스는 대개 두 후보 점수가 같아 `동점보류`로 빠진다(설계 의도 — 텍스트로는 결정 불가, 한 번 더 묻는다).

> 과제는 네 분류를 요구했다. `decide()` 에는 다섯 번째 결과 `LLM_TIEBREAK` 가 있어 이를 `동점보류` 로 따로 뒀다(합치면 오해를 부른다). 네 분류만 보려면 `동점보류` 를 "실행 안 함 = 안전 실패" 쪽으로 읽으면 된다.

## 5. 한계 · 유의점

- `candidates.py` 는 **수정하지 않았다**. 점수·임계값 로직 전부 원본 그대로 호출.
- 왜곡은 규칙 기반 합성이다. 실제 STT 오류 분포와 완전히 같지는 않다.
- 표면형 48종 전부(2음절짜리 `송금·창구·한전` 포함)가 3곳 이상 왜곡이 가능해 세 강도 모두 같은 표현 모집단을 라운드로빈으로 돌았다 — 강도 간 비교에 길이 편향 없음.
- 깨진 입력은 **캐리어 문장 없는 맨 키워드**다 ("음/저기" 정도만 붙는다). 실제 발화 "아들이 뭐 보내라는데…" 는 주변 맥락이 창(window) 매칭을 돕는다 → 이 측정은 보수적(하한)이다.
- 동점보류(LLM_TIEBREAK)는 프로덕션에서 facts 만 준 LLM 1회로 확정되지만 여기선 호출하지 않아 '실행 안 함'으로만 집계했다. 참고로 '1위가 정답인 비율'을 함께 실었다.
- 표본은 예시 데이터(김영자 님, 거래 3건 + 등록인 3명) 한 세트 기준이다.
